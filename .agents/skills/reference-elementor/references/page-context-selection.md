# 首页、分类页、详情页的组件与容器选型

本指南是固定 44 项之上的通用知识层。可查询规则位于 `D:/cloneWP/src/native44/page-context.ts`，不改组件名单，不添加单品或归档写入能力。规划前先加载本指南及本页涉及的组件档案。

## 1. 先判断真实上下文

根据实际来源所有者、查询状态、当前记录及截图确定页面职责。URL、域名、品牌、商品 ID、后台模板名称只能定位，不能证明它是分类结果或单品模板。

调用 `native44PageContextAdvice(pageRole)` 取得整页建议，其中 `pageRole` 为 `landing`、`archive`、`single-product` 或 `unresolved`；它不会自动猜测页面类型。再用 `native44ContextResponsibilityAdvice(role)` 查询具体区块的候选、依赖、证据和限制。上下文未确定时使用 `unresolved`，记录具名缺口，补证前不写入。

每页至少区分：

- 当前页面或模板自身的正文树。
- 由主题或其它共享模板提供的页头、页脚、菜单、Sidebar。
- 独立营销商品集合与当前分类结果。
- 当前单品事实与推荐商品、说明卡、社交链接。

共享页脚出现在浏览器中，不代表它属于当前 Elementor 模板的自有内容。已有页面仅作只读用法证据，不能因此修改共享区域或复制其资源 ID、表单动作和业务配置。

源码已研究、目标注册、已有实例、资源可用性、真实运行行为分别记录。账号权限能帮助读取真实上下文，不会扩大 44 项或自动授权模板修改。

本指南的非商品查询、Sidebar、表单、页面上下文、愿望清单和比较均为条件候选；当前 `desktop-browser-v1` 写入器尚无对应真实资源/上下文适配器，使用时在认证前具名返回 `unverified/unsupported`，不能以自填 ID、evidence 或 settingPath 通过，也不表示组件不兼容或已从 44 项移除。

## 2. 按职责选择固定 44 项

| 实际职责 | 候选及必要判断 |
| --- | --- |
| 静态页标题、主副标题 | `heading`、`wd_title`；说明文字用正文组件 |
| 正文、说明、附注 | `wd_text_block`、`text-editor` |
| 普通导航列 | `wd_list`，菜单模型匹配时 `wd_extra_menu_list`；不逐项做 Button |
| 图片、名称、说明及一个链接 | 优先 `image-box`，保持整张卡片归属 |
| 图标/图片、标题、副标题、正文及 CTA | 评估 `wd_infobox` 或 `icon-box` 的真实字段 |
| 真实行动入口 | `button`、`wd_button`；与导航列表和购买动作分开 |
| 固定目标商品推荐集合 | `wd_products`、`woocommerce-products`，使用既有真实商品和冻结查询证明 |
| 多组商品集合 Tabs | `wd_products_tabs`，每个集合单独证明及真实切换 |
| 静态内容 Tabs/FAQ | `nested-tabs`、`nested-accordion` 等对应内容模型；不能冒充商品详情与评论 |
| 已有 Sidebar | `wd_sidebar`，必须有现有 Sidebar 身份和实际渲染证明 |
| 上下文面包屑 | `wd_wc_breadcrumb`、`wd_element_breadcrumbs`、`breadcrumbs`，按真实提供器和页面上下文选择 |
| 社交链接/分享 | `wd_social_buttons`、`social-icons`，区分固定主页链接和当前页分享 |

完整卡片组件能覆盖字段时优先用完整组件；需要多链接、特殊顺序、独立编辑粒度时，记录具体理由再使用组合。颜色、尺寸、间距和字体差异不能作为拆散卡片或转 HTML 的理由。

## 3. 分类页：目录语义不能由外观代替

分类页常有标题/说明、分类导航、Sidebar、过滤器、排序/每页数量/视图控制、主结果及独立推荐区。先确认它们与同一个真实查询的关系。

- `wd_products` 的固定商品 ID 集合可用于营销推荐；当前适配器不能据此证明“当前分类结果”、筛选联动、排序和分页。
- `wd_sidebar` 能显示现有侧栏，不能仅凭存在就证明其过滤器能驱动当前页面结果。
- 静态 Button、Accordion、下拉外观不能充当分类过滤和排序服务。
- 普通草稿没有自动获得归档查询上下文。当前工具尚未实现真实 archive template/query 交付，核心结果或联动缺口必须报告。

已观察到的外围专业组件，如 `wd_archive_products`、`wd_builder_off_canvas_column_btn`、`wd_shop_archive_per_page`、`wd_shop_archive_view`、`wd_shop_archive_orderby`，只用于理解职责和必要合同。它们不在固定 44 项中，不能发现、编译或写入，也不能通过 HTML 模仿其业务功能。

若本次明确要求重建真实分类页，应交付分析和具名能力缺口；不能把普通草稿的固定商品区表述成完整分类模板。

## 4. 详情页：当前商品绑定是独立能力

单品页需确认面包屑、前后商品、图库、标题、评分、价格、购买、详情及评论都属于同一当前商品；推荐商品和静态服务卡仍是独立模块。

| 容易误选的替代 | 正确边界 |
| --- | --- |
| 普通 Heading/文本填写商品标题和价格 | 当前商品动态字段未受支持时，不静态复制来源事实冒充绑定 |
| 普通图片/轮播代替商品图库 | 可参考构图，不能据此证明变体图片、缩略图和选中状态 |
| Button 或 Form 代替加入购物车 | 需要当前商品、变体、库存和真实购物车合同；不能做假动作 |
| `wd_products_tabs` 代替详情 Tabs | 它查询商品集合；单品描述、参数、评论是另一内容模型 |
| `wd_testimonials` 代替商品评论 | 营销评价组件不能伪造真实 WooCommerce 评论集合 |
| `wd_compare` 代替单品比较按钮 | 它显示比较内容；加入比较的单品动作需当前商品绑定 |
| `wd_wishlist` 代替单品收藏按钮 | 清单内容与当前商品收藏动作分开处理 |

`wd_single_product_*` 的图库、标题、评分、价格、购买、Tabs、评论及前后导航、比较/收藏按钮，以及通知和价格跟踪等外围专用组件，只作 `reference-only` 研究，不进入写入器。普通草稿不能假称 single-product template；当前工具不新增单品 schema、动态记录绑定或模板运行支持。

只读研究与比较不加入购物车、提交评论、发送表单或产生业务记录。真实价格和商品事实必须来自允许的目标数据路径，不用 HTML、文本或伪元素补造。

## 5. 容器：按职责保留，不按层数处理

可用 `native44ContainerAdvice(...)` 对计划容器逐项判断；输入证据必须来自实际结构和注册合同。

| 应保留的职责 | 判断依据 |
| --- | --- |
| 视觉模块所有权 | 模块需要独立定位、验收或内容归属 |
| 行列布局 | 有独立 Grid/Flex、换行、对齐或 gap 规则 |
| 居中限宽 | 外背景与内部内容框宽度不同 |
| 背景与内边距 | 该层有独立背景、padding、圆角或局部叠放职责 |
| 重复卡片 | 多个控件确属同一项目，且完整卡片组件不适用已有理由 |
| 嵌套控件合同 | 实际注册合同要求直接子容器、slide 或固定数量内容容器 |

没有独立布局、视觉边界或所有权的计划包层，确认不影响嵌套合同、间距和自然流后才移除。即使只有一个子项，独立限宽或背景职责仍可成立。

禁止以下处理：

- 给每个标题、文字、图片、按钮都自动再包一个容器。
- 把控件运行时 DOM 的 `.wrapper`、Swiper、图片或按钮内部包装当作 Elementor 容器数量。
- 仅因层数多就批量删除，破坏外背景/内限宽、卡片项目或嵌套控件合同。
- 为了减少节点数，把原生内容合并成整段 HTML。

`composite` 才输出计划容器，叶子 Widget 直接输出；子树、实际 DOM 和编辑树分别核对。最终报告分别统计逻辑单元、实际 Elementor Container 与 Widget，不以“原生率”或最少层数替代合理性判断。

## 6. 交付边界

本规则层增加可查询知识，不扩充 44 项、安装插件或修改现有网站；也不声明所有分类页/详情页现已可生成。规划时采用当前支持的普通草稿路径，缺少真实上下文能力时保留阻断项。源站的外围专用控件不能借“已研究”取得写入权限。

学习和规划的实际操作范围由当前请求与任务记录确定；观察到现有模板不代表获准修改该模板或共享区域。
