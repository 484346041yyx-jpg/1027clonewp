# WordPress 接口会话与集中验收

站点凭据用于接口认证。组件生成、HTML 内容块保存、菜单绑定及发布通过已有受保护接口完成；浏览器承担来源观察、当前渲染与实际交互验收。接口写入失败不能切换为页面乱点保存，验收截图也不能代替所有权、CAS、意图和真实后台读回。

`WordPressConnection` 在一个命令内由页眉和正文共用。网关握手、能力目录和同名能力描述各读取一次，并发请求合并进行；返回副本防止调用方污染缓存。关闭会话后清除这些元数据，不跨命令保存。页面、菜单、商品、媒体及保护快照不使用这个缓存，每次实际操作继续核对当前状态。

配置 `wordpressNetworkRoute` 可选 `environment`（未填写时沿用进程原有连接）或 `direct`。该测试站根据此前连接重置和直连成功的实际证据设置为 `direct`；其它站点自行配置，不按域名硬编码。直连只覆盖该连接的精确目标源，使用 Node 原生 HTTP(S) keep-alive 池；HTTPS 保持默认证书验证。没有修改系统代理、环境变量、全局 fetch 或全局 dispatcher，也不增加运行依赖。显式注入 fetch 的测试/集成适配器自行负责网络实现。

线路在第一次认证前固定。失败不自动切线路、不自动重试 PHP；初始化失败可由调用方显式再做一次只读检查，已经进入或可能进入写入的请求保持原 pending 身份先对账。诊断只返回线路及计数，不保存凭据、请求内容、Cookie、会话 ID 或一次性 URL。

独立页眉连续 provision 步骤复用服务器刚返回且已经验证的完整响应，重新构造菜单/样式资源绑定，省去每步写成功后的重复 inspect。响应仅在当前进程内以精确对象保存；下一命令仍新读，下一写入仍带该响应的预期哈希并在服务器 CAS。未知、部分结果或保护漂移不进入复用路径。

静态富菜单的局部验收由 `src/woodmart-header/generic/menu-review.ts` 生成冻结宽度和稳定菜单/内容块选择器的计划。可用以下命令取得本地计划，无需认证：

~~~powershell
npx.cmd tsx src/woodmart-header/generic/cli.ts plan-menu-review --bundle D:/cloneWP/PATH/header --public-url https://example.com/task-page/
~~~

计划不是新鲜站点证据，也不代表验收通过。浏览器适配器必须使用当前工具明确支持的原生 hover/click，固定执行一次：视口→绑定观察→展开→等待真实稳定状态→截图一次→捕获后核对→恢复。每步默认 5 秒、单项总预算 18 秒，恢复另限 1 秒；适配器必须遵守传入的取消信号/工具超时。原生菜单内容、实际图片与链接、视口边界及截图前后文档/几何均需一致。返回 `captured` 后仍要查看真实截图作视觉判断。

当前浏览器工具若没有公开 hover 方法，执行器在任何 UI 输入之前返回 `hover_input_unavailable`。不得改用右键/Escape、拖拽、合成事件或改 DOM/CSS 冒充悬停。使用已有受支持的验收适配器，或者明确保留这项能力缺口；不能把它写成通过。商品推荐沿用已有真实商品验收，手机和整页的原质量底线不变；本地 fixture 不能替代当前页面视觉验收。
