# 复刻指令的范围

这是同一复刻系统的两种任务范围，不是另一套制作流程。来源观察、组件选型、原生设置、集中 CSS、响应式、视觉/交互验收、编辑器收尾和发布质量门保持原样。只适用于新任务；旧任务按已冻结合同续跑。

| 用户指令 | 制作范围 | 公共资源 |
| --- | --- | --- |
| `复刻网页：URL`、`复刻正文：URL`、新建任务的裸参考 URL | 页面正文 | 只读复用目标项目已有页眉、菜单及站点页脚 |
| `复刻页眉页脚：URL` | 公共页眉、页脚及各自依赖的菜单、内容块、媒体和隔离样式 | 创建本任务拥有、可重复使用的独立资源，不制作普通页面正文 |
| `复刻页眉：URL` | 仅公共页眉及其菜单、媒体和样式依赖 | 独立新资源及任务预览页，不创建页脚 |
| `复刻页脚：URL` | 仅公共页脚及其链接列表、媒体和样式依赖 | 独立原生 HTML 内容块及引用它的任务预览页，不创建页眉 |
| 明确要求“包含页眉页脚”或“整页一起复刻” | 用户指定的整页范围 | 按已有完整合同创建任务资源，不擅自替换其他页面的公共资源 |

“完整复刻流程”指制作与质量流程完整，不能据此把正文指令扩大为整页。`npm run create:replica` 仍接收代理生成的 preparation/full JSON；上表是代理的中文指令路由，不是新 CLI 或新的渲染器。

## 正文任务

### 指定正文板块

用户明确说只复刻截图或指定板块时，仍使用原 preparation v8 → full v4 的 body-only 线路。完整来源清单和桌面/手机证据保留；`sourcePartition.bodyUnits` 只包含选中板块，`unselectedBodyUnits` 保存本次未选中的正文单元。两者与 headerUnits、footerUnits 无遗漏且不重叠地覆盖 allUnits。未选正文不得伪装成页眉、页脚、浮层或从事实中删除。

该 opt-in 合同必须带 `sourcePartition.selection: {version:1,userInstruction,evidence:{path,sha256}}`；证据为本任务 `clonewp-body-selection-request` v1 JSON，绑定 taskId、sourceUrl 和同一 userInstruction。初始化和正式生成均核验真实文件哈希与身份；旧任务省略这些字段时沿用原语义。每个桌面来源视口必须有选中内容，未选单元无组件映射，选中与未选单元不得共享节点。准备只派发选中板块，保存、手机、视觉、交互、编辑器与发布门继续使用原链路；普通整页截图取证不因该声明缩减。新页路径按用户明确给定的路径，仍经 WordPress 唯一性核验。

用户明确指定独立新页路径时，selection 和对应请求证据同时记录 `targetSlug`，它必须与任务 slug 完全一致；该例外仅供新的 body-only 指定板块任务使用，不覆盖首页或已有路径。完整来源包和独立清单仍保留全部内容；`captureScope.selection` 只将选中区域纳入辅助截图的呈现等价校验，未选正文、复用页脚的排除理由分别为 user-unselected-body、reused-footer。选中内容仍逐节点核对文字、结构、媒体、样式和几何；原始及辅助包均保留，未选区域的计数器等动态状态不变成制作义务。

等价视口截图必须保留实际内容宽度、可量测区域覆盖和前后状态。物理截图事务及原始媒体证据如实记录辅助视口，不伪填为标准桌面视口。导入器在完整等价证明通过后，生成带原始证据引用、captureViewport 和 captureScopeHash 的标准来源投影；原始文件不改写。原任务和无 selection 的合同保持原有检查。

准备材料中的每个 source unit 须从真实 observation packet 收集该区域的完整 nodeIds，包含无文字的容器；不能仅用 source facts 中出现的节点代替完整 DOM 归属。sourceFactIds 仍完整且唯一分区，未选单元的 componentKeys 为空。bodyBase 的标准桌面视口直接使用 native44ProfileViewports 的配置身份，手机视口仅进入 responsive；启用原生图片策略 v2 时素材文件使用 `{assets:[...]}` 外层结构，所有文件与字节哈希在派工前冻结。以上材料格式沿用现有执行器，不另设板块保存入口。

1. 先确认当前目标站和项目，读取实际使用的公共页眉、菜单和页脚。按本次明确指定的资源或该项目已核验记录定位；不能按最近任务猜 ID。缺少或有歧义时先定位资源，不自动生成、替换或改全站默认。
2. 保留原站完整取证与内容清单，但把页面级页眉、页面级页脚和正文分开，明确前两者为复用范围。文章内、卡片内的 footer 仍属正文；正文末尾的 CTA、订阅区等不能只因位置靠下就排除。页面级页脚缺乏可靠语义或观察分区时先补证据，不扩大排除范围。
3. 继续使用 preparation v8 → full v4 及原来正文编译和验收链路。新正文合同冻结 `pageScope: "body-only"`、`reusedHeader`，后者由 `inspectReusedHeaderResources` 带相同 `pageScope` 只读取得，包含 `footerHash`。`sourcePartition.allUnits` 保留整个清单，`headerUnits`、`bodyUnits`、`footerUnits` 精确分区；footerUnits 可为空，但不能省略实际存在的页面级页脚。页眉/页脚单元的 componentKeys 为空，制作组只分配 bodyUnits。
4. 不创建页眉、菜单或页脚；不写公共资源。新页面保留公共页脚、页脚前区及版权区，不再套用历史整页模式的关闭页脚设置。既有共享内容、主题配置及菜单在写前/读回均受指纹保护；变化即停止对账，不覆盖。页脚指纹保守涵盖共享 HTML 块、布局及菜单依赖，可能因其他共享资源同时修改而失效。
5. 正文仍逐项对照来源制作；最终在实际公共页眉页脚包围下检查桌面和手机的间距、菜单、页脚及正文交互。公共部分对照冻结的目标资源，不要求它们长得和本次正文来源站相同。不降低任何正文质量门。

## 公共页眉页脚任务

页眉和页脚是可复用资源，不能塞进每个页面正文。继续用既有原生页眉模块和 WordPress 菜单职责；页脚采用目标版本确实支持的独立原生 HTML 内容块或页脚布局，内部仍用启用的原生组件与同一编译、样式和响应式规则。制作前核实原生页脚文档类型、保存和绑定适配；缺适配明确报告，不能把正文页冒充公共页脚交付，也不能将原生菜单内容块的组件限制擅自放宽。

三个公共指令分别冻结 `pageScope: header-footer / header-only / footer-only`，使用同一 `create:replica` / `replica:full` 入口的 version 5 公共资源合同。页眉调用现有 Header Builder 模块；页脚沿用 native44 组件知识、实际注册、原生编译和 responsive 适配，保存目标为本任务独立 `cms_block`。预览页通过原生 HTML 块短代码引用它，不复制一份页脚。页脚内容及设备证据必须属于来源 footer 区域；悬停仍经过相同的三态来源验证，不能因不制作正文而省略。

明确由用户自行检查的任务可冻结 `deliveryPolicy: draft-for-user-review`，仅交付未绑定的草稿资源，不把结构保存成功写成视觉或交互通过；此策略不授予发布或修改全站设置的权限。普通任务的发布质量门保持原规则。公共资源合同的预览路径是具名任务预览用途，可独立于来源首页路径；不占用或替换目标首页。

本指令授权制作本任务公共资源；绑定范围须是本次目标项目，不从“公共”推导出替换全站旧页眉、旧菜单或旧模板的授权。不自动改旧页面、商品、系统配置或插件。预览/验收需要页面时只创建具名的任务自有预览页，并在清单中说明用途、状态和去留；不复制无关正文。原来要求的实际双桌面、双手机和编辑器验收继续适用。

交付列出页眉、页脚、菜单、样式块和预览页的真实名称、ID、后台编辑链接、状态及实际绑定范围。下一正文任务只读引用这些已核验资源，不重新生成一份。修改公共页眉页脚须用相应指令或明确指名授权，不能由普通正文修正隐式触发。
