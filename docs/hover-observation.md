# 通用悬停取证

新来源采集使用 `src/replica-v2/collect.browser.js`。采集器读取当前可访问且当前媒体条件生效的 CSS 规则，把可见元素匹配到的 `:hover` 规则登记为 `kind: hover, status: declared`。这只是待观察清单，不能当作已验证效果。被浏览器跨域限制而无法读取的样式表会留下 `hover-stylesheet-unreadable` 缺口；CSSOM 也无法穷尽 JavaScript 鼠标监听器。观察员还须检查明显的按钮、导航、图片卡片等交互区域。

按不同悬停规则选择代表性触发元素，不逐个重复检查同类链接。对每个选中的代表使用浏览器适配器**真实鼠标悬停**，依次采集默认、悬停、移开恢复三个状态及各自截图。每次在同一页面调用只读 `collectHoverStateV2`，传入来源 URL、来源包中的唯一 `triggerSelector`、受影响元素的唯一选择器、对应 `stage` 和实际截图 SHA-256。采集器会核实真实 `:hover` 状态，记录元素及伪元素的计算样式、尺寸、媒体来源和时间。没有原生 hover 能力时标记能力缺口并停止该项，不能用拖拽、右键或合成事件冒充。

连接的 Chrome 开启完整 CDP 访问时，先从实时标签的 `tab.capabilities.list()` 确认 `cdp`，再用 `tab.capabilities.get('cdp')` 读取当前接口文档。设置刚启用但旧绑定仍无 `cdp` 时，重建控制会话并重新绑定**同一来源标签**，然后重查能力；不得仅凭旧绑定的清单认定 Chrome 不支持悬停。CDP 可用时，从只读 DOM 几何确定可见触发点，以 `cdp.send('Input.dispatchMouseEvent', { type: 'mouseMoved', x, y, modifiers: 0, buttons: 0 })` 移入；这会经过浏览器输入管线更新 `:hover`，不发送点击或页面脚本合成事件。采集后移至经 `elementFromPoint` 核实的中性位置，等待页面菜单过渡稳定，再核对触发元素 `:hover` 从 `false` 到 `true` 再到 `false`，并核对对应面板的实际开合。若中性点路径经过别的导航触发器，继续移至不会触发菜单的位置并重新读回，不把过渡帧当恢复态。CDP 对特定站点要求授权时按浏览器弹窗处理，拒绝或未暴露能力时保留具名缺口。

把三态与截图引用写成 `source-hover-review`，放入 `sourceEvidence.additionalEvidence`。准备入口会核对每种已声明悬停规则至少有一个真实代表，并逐项核对已选代表的节点、顺序、指针状态和截图散列；缺少某种规则的代表在认证目标站前失败。生成阶段按实测差异选择原生悬停设置或任务作用域 CSS；最终在来源与目标的相同状态核对颜色、下划线、位移、缩放、伪元素、媒体与恢复状态。旧来源包没有这类事实，不自动迁移或改变旧任务合同。

普通多级导航只需针对确实有子项且来源以悬停打开的父项配置和验收；没有子项的普通链接不应被强制改成悬停菜单。独立页眉的 `menus[].dropdowns` 为这些父项按稳定 `itemKey` 记录面板宽度、相对导航底边的偏移和文字颜色，编译时根据本任务实际菜单项 ID 生成隔离样式。未观察到的状态不能靠默认样式推断为复刻完成；该配置不代替最终真实移入、进入面板和移开后的检查。
