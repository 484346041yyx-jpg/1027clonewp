# 原站信息完整性

新来源先建立独立于目标组件的全内容清单，再制定组件与样式方案。使用项目现有采集器的全页 `sceneInventory.content`，保留文档中已加载的可见及隐藏文字、所有链接及地址、媒体、控制项和装饰线。按实际位置保留重复内容，不按文本相同去重，不按目标 44 组件能力删来源内容。表单填写值不进入这份清单。

来源导入在选择组件之前自动输出 `source-completeness.json`，`job.json` 返回其路径。逐项比较独立清单与采集包的文字正文、链接地址、媒体和样式记录，不能仅以节点存在或总数一致认为内容完整。未分配板块的隐藏内容也保留为缺项。报告中 `captured` 仅证明当前已加载文档与声明状态范围内记录一致；无法穷举任意网站未来请求、登录区或第三方内容。

代理先读报告，再选组件。缺文字、链接或媒体时补对应范围采集；标签、折叠、轮播、计数器的默认、变化及恢复状态未观察时具名保留，按不同实现和内容变化补正常操作取证，不以静态 DOM 冒充交互观察。懒加载需正常滚动到底、等待资源与布局稳定后补采；iframe、canvas、Shadow DOM 不能只看外框即算完成。不能读取的内容明确记录，不编造、不悄悄删掉，也不建立无限重试关口。检查完来源才进入制作；已有采集缺口随事实传入后续任务，制作完成不能反过来证明来源完整。

旧观察缺少独立全内容清单时标记 `unassessed`，不迁移或伪造历史通过。本增强不操作远端页面。
