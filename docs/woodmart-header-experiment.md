# 独立 WoodMart 页眉测试路径

本目录对应的实现位于 `src/woodmart-header/`，由用户明确授权的新测试方案启用。原 `native44` Elementor 组件路径、旧页面与旧菜单不迁移、不删除。

首次部署顺序：读取目标主题真实源码和页眉/菜单/页面引用，保存写前基线；若现有 test 为默认，先创建当前结构及已保存 CSS 相同的保护副本，再将全站和预设中的默认引用指向副本；确认前台相同后建立独立 test 菜单及新页面；保存 test 页眉和新页面样式；完整桌面与交互复核后发布新测试页。

`contract.ts` 是语义计划、链接、隔离和 CAS 合同；`transport.ts` 复用项目已有 Novamira 网关但不授予资源所有权；`layout.ts` 只构建显式页眉树；`presentation.ts` 仅生成新测试页限定的 CSS 与说明正文；PHP helpers 负责目标实际资源读写。任意 PHP 的只读语义不能由传输层标签自动证明，只有经审查的固定 helper 可进入此路径。

本次测试对象为 `header_193941`，新菜单 `test`。复制页眉的内部元素 ID 和样式保持；修改 test 的桌面元素使用新的独立 ID。菜单 ID 与 slug 必须在目标站同时核对，不能把来源对象 ID 带入目标。普通下拉使用 WordPress 父子菜单；本次不需要 HTML Block。

测试页的内容链接保留参考站公开地址，Home 指向新测试页，账户和购物车使用目标 WooCommerce 原生组件。原生账户名称和购物车数量/金额格式会随真实登录及购物车状态变化。桌面验收范围为 1920×1080 与 1440×1000；不宣称手机已复刻。

本地 `tools/header-*.ts` 是本次实验的显式入口，尚未并入旧页面生成器。远端变更串行，写前意图落盘、服务端快照匹配、读回对账；未知响应只读对账，不能盲重发。任务完成后临时 JSON、截图和中间文件按项目清理规则删除，源码、说明和测试保留。
