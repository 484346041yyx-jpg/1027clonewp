新任务询盘表单沿同一线路配置原生提交、后台保存和项目邮箱通知，字段与样式按各站实际来源适配；发件设置自动生成。testing:user-managed：只核对配置、控件、样式与保存读回，实际提交和收件测试交给用户，不自动发测试邮件。见 [通用询盘表单默认要求](inquiry-forms.md)。旧任务和已发布页不迁移。

当前新任务使用 preparation v6 冻结逐板块正文保真检查与可量测桌面样式目标，再合并成同一 full-replica v4 执行合同：桌面＋手机共同规划和验收，手机关键决定在分工前冻结，平板沿用桌面；实现与合同见 [并行方案准备](parallel-replica-preparation.md)及[手机响应式能力](replica-responsive.md)。旧任务保持原合同，不自动迁移。

新任务先按 [复刻指令范围](D:/cloneWP/docs/replica-command-scope.md) 确定正文或公共页眉页脚职责；普通“复刻网页”默认正文，只读复用公共部分。下文原完整制作与质量流程不变，其中创建页眉/菜单及关闭页脚的整页行为仅适用于相应范围或历史冻结合同。

新任务的执行减耗默认冻结 `editorCompletionPolicy.runtime=shared-owned-editor-v1`，按 [编辑器运行与续跑约束](D:/cloneWP/docs/editor-completion.md) 使用统一任务身份和持久恢复状态、兼容检查共用编辑器上下文；临时编辑/还原后新载模型，最终重开仍独立。生成与修订前集中关联决定和CSS，完全相同的CSS经fresh保护读回后零写入；证据缓存仅限单次验收并在返回前重新核验。桌面/手机视觉、交互、原生可编辑性、保存还原与当前版本验收标准不变，旧合同和组件实现不自动迁移。

# 完整复刻：独立 WoodMart 页眉与原生正文

新任务按 [通用三步复刻](three-step-replica.md) 先完整采集，再确定区域主要容器及内部关系，最后选组件并自外向内制作。准备包和合并产物共用 `productionGuide` v2。制作中的代表性实际输出核对用于尽早修正结构和默认外观，不等于增加逐组件正式整页验收；最终整页验收仍沿用冻结合同。视觉未知项可以具名继续候选制作，不能被映射或保存成功冒充通过；旧任务不自动迁移。

轮播及商品标签切换控件在来源取证时逐区记录前后按钮的可见状态、实际 SVG 或伪元素图形、盒子尺寸和桌面/两个手机宽度的差异。生成时优先使用已验证的原生图标控件；来源图形不同于原生选项时，保留原生切换行为，仅在当前组件稳定类名下绘制对应图形。不得只写 `arrows=yes` 后接受 Elementor 默认 chevron，也不得接受 WoodMart 商品标签的默认图标字体。来源无商品轮播箭头时，生成结果须在全部宽度隐藏该组件的原生箭头，不能只在手机断点隐藏。v3/v4 正文准备会检查来源箭头与显式图形/隐藏映射，缺失时在远端写入前失败。整页验收须逐一核对桌面与手机当前页的实际图形、位置和显隐，并用正常指针点击前后按钮确认轮播变化及可还原；按钮即使可见，`pointer-events:none`、图片覆盖或无法命中都算失败，不以强制点击、程序调用或单元测试代替。

当前创建统一使用 `npm run create:replica -- PREPARATION.json` 或完整 manifest。组件编译由 native44 提供，已移除独立组件页面及旧执行器入口。当前任务按自身冻结证据验证，不自动迁移旧锁。

## 输入与并行准备

新 preparation v6 的正文任务包自动包含 `productionGuide`：逐板块、逐桌面宽度展开来源文字全文和行数、内容框尺寸、字体、四边边线、图片数量及布局、交互类型和实际观察状态。制作时按这些来源数据选择当前 44 组件和原生设置；行数不能直接变成强制换行，先确定字体、文字可用宽度和间距。合并会输出 `production-guide.json`，将同一批要求对应到实际配置组件；只把来源事实挂在外层容器上的文字/媒体保留为 `unmapped`，不能当成已制作。`mapped` 仅表示已有组件认领，仍须确认组件内容、实际显示和操作。清单不阻断进度，不复制原站指令，也不改旧任务。

新 preparation v6 准备合并会写出 `build-diagnostics.json` 并在命令结果返回其路径与数量。它从来源桌面几何和实际 Native44 组件树预警两类常见的制作错误：并排来源子组没有原生横排容器，以及来源真实表单被静态文字/按钮替代。预警不阻断下一步，也不宣称 CSS 或表单功能已经通过；制作人应先检查对应容器或控件，能修则在首次远端写入前修正，受当前 44 组件能力限制的保留具名缺口。最终仍以实际渲染和交互复核为准。

新完整任务使用 `clonewp-full-replica` v4 manifest，省略版本时默认4，省略 headerProvider 即 `woodmart-header-builder`。它冻结来源证据、实际 header/body 来源单元分区、独立页眉计划/菜单/CSS/新素材清单、正文 native44 program/CSS/单元映射及各文件 SHA-256；`responsive.version:2` 同时冻结生成前手机决定。显式历史v1/v2仍按自身版本读取，不自动补新决定或迁移。未知 provider、来源重叠、遗漏、失效引用在认证前失败。

用户明确要求复用既有页眉时，新 preparation v8 可使用任务级 `reusedHeader`，省略 `headerBase` / `headerAssets`，仅派正文准备组；完整 v4 合同对应 `headerProvider:'reused-woodmart-header'`。先用 `inspectReusedHeaderResources` 只读核对真实页眉、菜单、内容块及保护哈希，不按历史业务 ID 猜测。执行仍走同一新任务自有页面与原生正文流程，只在该新页面绑定已核对页眉；既有共享资源不取得写权限，不伪造自有页眉 checkpoint，不支持页眉样式修订。桌面、手机来源和整页验收不豁免；已有合同与默认自建页眉策略不变。

完整manifest之前新增独立 `src/replica-preparation/`：先冻结同任务真实来源、共享设计规范、关键能力及兼容决定，再通过当前任务协作工具并发产出页眉/菜单和最多两组正文配置。准备代理只操作各自精确输出，只有协调者操作共享浏览器、共享规范和最终合并；依赖相连的板块同组。能力未知、协作不可用、来源/分组冲突或结果不完整时，在远端认证之前阻断。独立模块不加载凭据、不操作WordPress、不修改旧组件实现。

完整manifest内的页眉/正文 `Promise.all` 只并行读取、校验已形成的方案，不能代替上述真实方案产出并发。正文仍由原native44编译器生成，受启用44身份、实际注册控件/子树、本地知识交集和当前进程编译证明约束。源事实由实际两桌面typed packets重新派生；程序递归事实映射必须恰好属于正文单元。来源真实header/banner的全部后代不得归入正文；实际程序包含header/banner或已知页眉语义时拒绝。不能仅凭自报embeddedHeaderCount=0放行。

来源取证继续使用用户连接浏览器，保持实际1920×1080及1440×1000。整页截图若临时去滚动条、改变吸顶脚本宽度或布局，不能拿错宽长图充作正式证据；改用稳定的普通视口截图/分段，保留实际像素、几何及来源包。隐藏动画、懒加载、折叠和轮播需要正常UI预热及实际可达状态，不能当作无内容删除。

新采集器发现的 CSS 悬停触发者必须按 [通用悬停取证](hover-observation.md) 完成默认、真实悬停、移开恢复三态及截图；准备入口在认证前核对覆盖。独立页眉的菜单状态在方案阶段按 [页眉通用状态效果](header-hover-effects.md) 映射，不留到远端写入后猜测或补专站 CSS。仅有静态来源截图或 CSS 声明不算已验证悬停。旧任务沿用自身冻结来源，不追补此项。

## 原生设置优先

新任务在正文方案合并前按 [容器树与内容对齐线](container-tree-layout.md) 冻结父子方向、内容轨道、子项占比及设备变化；生成后的草稿如需经用户授权修树，使用 `replica:full revise-layout` 的原生容器补丁和当前指纹读回，不以 CSS 模拟缺失的父子结构。旧冻结任务不自动迁移。

新任务默认冻结 `nativeImagePolicy`：内容图片使用原生图片控件，容器照片使用原生背景图片控件及本任务媒体，不能只写在 CSS 中。CSS 只补充原生设置无法表达的裁切、布局或装饰；不得用 `background` / `background-image` 的图片 URL 覆盖可换图控件。渐变遮罩与照片分开，优先使用原生背景覆盖。确实缺少原生控件时，记录精确组件、原因和目标版本证据后才能使用例外。旧任务的冻结合同不自动迁移。

验收检查原生面板缩略图和媒体引用；对不同实现选代表图片，实际通过面板临时替换、核对画布或预览的图片确已改变，再恢复原图并核对最终读回。不能只凭 JSON 合法或面板有值判定换图可用。换图检查保留前、替换、恢复证据，并绑定当前页面指纹；不将临时替换发布到访客页面。

先按参考站外观和交互核对目标当前版本的原生设置与模板语义，再选择行列、菜单、图标、显示、展开和吸顶配置。原生选择能完成的显示行为不再用CSS强行重写。原生没有的细节才用本页眉作用域CSS补充，并记录差异和理由。参数名称或数值相似不能证明视觉含义相同；例如账户的Only text、购物车的Icon with text、Background wrap type必须分别依据实际合同。

在分工之前集中决定会影响整页的字体/字重、主题页面壳和内容宽度、页眉换行、原生交互与减少动态效果行为。v3/v4还须从两个手机来源确定图标/文字角色、排列和间隙、产品实际同屏数量与原生字段映射、整条手机页眉的滚动行为及偏移；具名用户要求作为显式覆盖保存，来源事实保留。决定冻结到同一响应式合同，各组不得自行默认数量、定位或靠子节点序号猜角色。优先复用同任务已取得的真实观察，以及适用于当前版本的已验证知识；历史业务ID、通过结论和旧截图不复用。未知组合只读核实相关控件与依赖，不检查无关全部组件，不为每个新任务额外建测试小样。避免把这些决定留到整页写入后再返工。

生成前代码核对来源角色及几何、来源产品实际可见卡片、页眉滚动交互和两视口覆盖，再检查合并程序的原生手机数量是否对应决定、页眉Mobile滚动决定是否一致、基础及手机CSS是否使用容易受编辑器额外节点影响的容器顺序选择器。先选择能表达决定的原生配置及稳定组件类名；缺适配时在认证前阻断。最终验收仍要验证浏览器实际结果，不能用通过静态校验代替效果。

每个任务自动创建独立header、WordPress菜单、样式块、Full Width页面和必要新媒体。素材只从本次实际来源及明确转换证据准备，不写死历史页面/菜单/附件ID。来源字体轮廓可派生自定义SVG图标，但保留原文件哈希及转换记录，不用猜测图标。

## 串行执行

远端阶段严格串行：新模块保留身份并创建唯一Full Width草稿 → 导入页眉新素材和创建菜单/样式块/页眉 → 导入正文素材、原生编译并完整保存正文 → 保存独立正文CSS → 绑定页眉 → 统一实际复核 → 发布。

先创建草稿是因为新素材导入需要精确owned draft；它不会创建Canvas或接管旧页。主题页脚若由正文复刻，对本任务新页使用经目标源码核实的页级禁用开关，避免双页脚。全站默认页眉、主题选项、菜单位置、旧页和旧菜单保持保护。

Full Width 模板仍可能受到 WoodMart `negative_gap` 的限宽和40px内容间距影响。新页默认以原生页级开关关闭主题标题/面包屑和侧栏；正文 CSS 编译器自动附加精确 `body.page-id-ID #main-content.wd-content-layout` 固定壳层规则，将本页内容区通栏并归零间距。调用者的正文 CSS 仍只能作用于自身 Elementor 根，不开放任意祖先或全局选择器。已存在的本任务草稿可用固定 `shell` 适配动作设置这两个原生值，正文及全站选项保持保护。

CSS-bearing Elementor 文档使用显式编辑器控件模式和不复制响应式默认值的全新文档实例读回。新流程的独立原生页眉适配层仅对所有权和runId均匹配的任务页排除 `_elementor_page_assets`、`_elementor_controls_usage` 两个派生缓存；原页眉适配器文件和保护对象检查不改。未知结果仍先对账，不能借缓存归一跳过真实内容或菜单差异。

每个远端阶段先持久意图与预期检查点；使用项目目标写锁、任务锁、服务器资源锁及CAS。响应未知保留pending，先只读reconcile，拒绝盲重试或重复创建。正文、页眉和菜单独立更新，不能用CSS隐藏重复页眉代替正确的结构分区。

公开的双下拉等 GET 导航表单使用独立 `src/replica-full/navigation-form/` 适配；`navigationForms` 从真实双桌面 DOM 补充证据冻结 action、method、字段名、选项值及标签，并与来源包交叉核对。只允许同来源 HTTPS GET、select/options 和 submit，不支持 POST、隐藏凭据、任意脚本或业务提交。正文先用原生组件保留标题/说明及唯一自有容器，适配在串行保存中追加精确表单，保持其余树和设置不动。最终两桌面都实际选择非默认项并提交，核对完整目标 URL 与 query；WordPress 添加一个路径尾斜杠可作为规范化跳转，其余路径变化不放行。该能力不改变旧组件 HTML 白名单或旧 native44 编译器。

## 执行速度约束

普通复刻任务不运行平台全量 `npm test` 或 `npm run build`；使用本任务编译/写入校验和实际页面视觉、交互验收。只有修改系统源码时，开发期间跑相关专项；源码冻结后完整测试与构建各一次。完整测试需要本地浏览器和路径 fixture 权限，先使用适合的测试环境，避免在不具备权限的环境跑一轮后再重跑。

来源的两桌面完整观察及未变化的项目知识在同任务内复用，保留各自文件哈希；不为页眉、正文、CSS分别重抓同一份来源，不继承旧任务的业务资源或完成结论。页眉和正文按统一分区并发产出方案，正文按真实布局/控制依赖分组，不能为均分数量拆散相关状态。本地素材处理可与方案准备重叠，所有远程写入仍串行。原生样式先定好，再集中补一份作用域CSS；局部修正先看受影响区域，最终当前版本统一验收两桌面一次。交互按不同原生实现、实例差异及边界状态选代表操作，同类重复项目的数据仍全部检查；不对每个同构项目机械重跑同一组操作，不把旧指纹证据改标为当前通过。

记录取证/共享规范、各组方案产出、本地合并与处理、远端保存、修正和最终验收的实际时间。准备组记录真实开始与完成；并发阶段记录整体wall time和各组耗时，不能把各组之和当作用户等待时间。保留失败/重试开销，未覆盖的人工或浏览器阶段明确未测量；正常复刻与首次系统开发/测试分别统计，不因缺数据宣称提速比例。计时只是诊断，不是额外通过条件，更不能用预算替代完整质量门。

协调者对自有已存在材料目录使用 `replica:prepare phase`，在取证/共享规范/素材/最终视觉各阶段开始时记录marker，成功、失败或取消均及时收尾；阶段与命令见 [并行准备计时](parallel-replica-preparation.md)。最终读取材料目录的 `phase-events.json` 及准备/远端timings两处实测，state未关联外部日志的未测量字段不覆盖外部已测量阶段；纯模型时间未测就不报告。

同一命令的发布核验只使用一次完整证据核验和一次最新远程快照。新模块的 `review-barrier.ts` 在内存中保留单次、最长30秒且绑定验收对象与完整页眉/菜单/正文/CSS指纹的快照，交给本命令下一步发布；跨命令、内容改变、超时或已消费均重新核验。发布仍带原快照预期哈希、保护哈希、持久意图和服务器CAS，远程内容被并发修改时拒绝写入；没有持久化快照快捷通道。等待实际资源与UI状态，不用固定长暂停或无变化轮询；满足当前质量底线就交付，不额外增加能力试验或反复全站检查。

## 统一检查和交付

接口连接与菜单验收按 [会话调度](wordpress-session.md) 执行：共用当前命令的网关会话，衔接已经验证的保存响应，不重复建立连接或读取同一能力描述。页面资源及并发保护继续新读；浏览器按受影响菜单和冻结宽度集中捕获，缺原生 hover 时保留具名缺口，不右键或拖拽模拟。

本次最终保存/发布和视觉交互验收完成后，代理必须自动执行 [编辑器版本收尾](editor-completion.md)。新任务冻结 editorCompletionPolicy；只对齐当前任务拥有页面的已知旧自动保存，正常重开并读取实际文档模型及截图，再运行 editor:complete verify 和本流程 status。没有确认正常重开时，即使已发布，complete 也保持 false；不重写旧合同或处理其他页面。

`run`完成整页及CSS后停在awaiting-review，不能把保存成功标成视觉通过。统一复核两桌面完整模块、真实文案/媒体/字体/间距、可编辑性、无溢出、单一WHB页眉和正文无页眉，以及菜单、键盘、吸顶、账户、购物车和所用折叠/轮播/文章列表；访客和登录文案均在最终发布前纳入布局检查。表单若只有安全原生pending布局，明确未接通业务，不能声称订阅成功。

实际截图、浏览器DOM、交互前后证据及人工判断绑定当前page/body/CSS/header/menu/style指纹。`review`验证文件哈希与实际截图尺寸、解析真实DOM的页眉计数，并fresh读回资源。`publish`再次核对当前指纹，只发布精确新页面。v2/v3/v4 手机必须有真实来源、两手机实景与实际菜单交互证据，以及平板沿用桌面的断点证据；v3/v4额外要求两手机宽度各自的前台和Elementor编辑器实际角色几何/图标绘制、产品同屏数及页眉顶部/向下/向上/开菜单证据，与生成前冻结的来源决定核对。普通、固定、向上出现按目标或具名用户覆盖判断，不把所有网站写死为2个产品或固定页眉。旧合同不借新规则冒称新增能力已通过。

v4 还在发布审核前逐区比对手机来源与目标的真实计算样式、文字行数/框高和实际内容宽度，并对每个手机轮播比对来源与目标的滑动前后卡片位置和逻辑步长。报告必须来自当前页面指纹下的浏览器实际状态；CSS 文件保存成功或轮播首帧看起来接近，都不足以通过。格式见 [复刻视觉证据检查](replica-visual-audit.md)。

```powershell
npm run create:replica -- D:/cloneWP/references/TASK/full-manifest.json
npm run replica:full -- status --run-dir D:/cloneWP/runs/RUN
npm run replica:full -- review --run-dir D:/cloneWP/runs/RUN --evidence D:/cloneWP/runs/RUN/review.json
npm run replica:full -- publish --run-dir D:/cloneWP/runs/RUN
npm run replica:full -- reconcile --run-dir D:/cloneWP/runs/RUN
npm run replica:full -- rebase-current-draft --run-dir D:/cloneWP/runs/RUN --expected-fingerprint OLD_SHA256 --current-body-hash CURRENT_BODY_SHA256 --current-document-hash CURRENT_DOCUMENT_SHA256
npm run replica:full -- recover-style --run-dir D:/cloneWP/runs/RUN
npm run replica:full -- revise-style --run-dir D:/cloneWP/runs/RUN --css D:/cloneWP/references/TASK/body-revision.css --expected-fingerprint CURRENT_SHA256
npm run replica:full -- revise-header-style --run-dir D:/cloneWP/runs/RUN --css D:/cloneWP/references/TASK/header-revision.css --expected-fingerprint CURRENT_SHA256
npm run replica:full -- revise-native-motion --run-dir D:/cloneWP/runs/RUN --expected-fingerprint CURRENT_SHA256
```

`revise-style` 仅针对本任务已绑定、未发布的草稿；先验证当前完整指纹，再独立保存新正文 CSS，保持原程序及冻结 CSS 文件不动，并清空旧审查，返回待复核状态。`revise-header-style` 同样验证完整指纹，只修订独立页眉样式，保持正文、菜单、布局和字体配置不动；哈希绑定的修订链授权新有效样式，原输入保留，旧审查失效。菜单和布局继续沿各自独立 bundle 维护；更改后需绑定实际新状态重新验收。

`rebase-current-draft` 仅在用户明确同意保留当前草稿、布局修订写前失败且没有远端写入意图时使用。它对照已确认的旧读回、当前正文结构、精确页面归属、页眉与收据，并要求调用者提供当前正文及 Elementor 文档哈希；只更新本地受保护基线和本任务页眉检查点，不保存远端页面。浏览器仍有未保存更改时，不刷新编辑器或继续页面写入；先让用户处理，再重新取证。

`recover-style` 只处理正文阶段已经保存准确正文及 CSS、却因服务器执行上限留下 started 回执的任务。先只读对账，再显式执行恢复：重新用当前控件、原生序列化、冻结输入和已确认媒体编译，对照全部元素和页面设置；新增默认值须来自实际注册控件。必须找到晚于原意图的真实服务器超时日志、匹配原操作的自有锁、原 payload 哈希和完整 CAS。恢复只确认原回执并释放该中断操作的精确锁，不重存页面；外来设置、未知媒体、活跃编辑锁或没有终止证据均拒绝。普通 reconcile 不执行 started 回执修复。后续 CSS 写入使用已核实的 Document.save settings-only 分支，避免为 CSS 重复渲染整个商品树。

当实际浏览器“减少动态效果”与目标主题的0秒过渡造成原生嵌套轮播卡住时，优先选择原生过渡时长0。`revise-native-motion` 先核实目标当前注册 `nested-carousel.speed` 数值控件允许0，只修订本任务未发布页面内该控件，保留内容、其余设置、CSS和页眉资源。修订前后树及完整保护指纹、回执和控件ID独立记录，旧程序不覆盖；审查失效后重新验收连续前进、返回和循环。不得用强制可见动画覆盖浏览器的减少动态效果偏好。

交付必须直接列出页面地址/ID、页眉名称/ID及后台入口、菜单名称/ID及后台入口、独立样式位置、源码/配置路径、实际验证范围和未验证能力。页眉布局/菜单/样式留在独立bundle，正文程序与CSS独立维护；两套历史实现保留，不因为系统新默认而迁移。

最终面向用户的回复直接使用 `delivery.resources` 中真实的 `header.name` 和每个 `menu.name` 作为链接文字，例如“页眉：HOSHIICHI — WoodMart Header；菜单：HOSHIICHI — Replica Menu”。不得将名称概括成“WoodMart 页眉”“菜单”，也不能只在链接目标或本地报告中保留名称。
CSS 修订使用原生 settings-only 保存后，必须重新取得当前文档，再调用 CSS 文件生成；Elementor Pro 的页面 CSS 钩子会读取文档管理器缓存，保存成功本身不能证明前台样式已更新。仍须核对实际页面加载的样式和画面。

若 CSS 修订已完成、运输回复丢失，`reconcile` 只在实际 complete 收据、原操作 payload 哈希、任务持久化写前快照及完整原检查点全部吻合时接受结果。只允许 custom_css 与本页派生哈希变化，元素、其它页面设置、页眉、菜单、全局保护状态和其它收据必须一致；它只补本地确认，不再次保存或远端补写收据。started 或第三状态继续阻断。
# 图片清晰度选择（新准备任务）

新准备任务的 `nativeImagePolicy.version=2` 在合并后、远程认证前核对原生图片控件所引用的素材实际像素与来源卡片显示尺寸。同一来源图片的 WordPress 尺寸变体以去除文件名末尾 `-宽x高` 后的完整来源 URL 归组；只在已导入、字节哈希正确的同组素材中提升明显不足的版本。若约 80px 以上的图片以不足 0.85 源像素/显示像素呈现，而同组没有达到 0.95 的候选，准备阶段明确报出组件与尺寸，要求补取来源图，不用 CSS 锐化或猜测 URL。选择记录写在本任务合并目录的 `image-resolution.json`。冻结的 v1 任务不自动更改素材或合同；最终前台仍需目视检查构图与清晰度。

若来源图片与卡片显示比例相差超过 15%，WoodMart 图片控件使用本任务已导入媒体的完整 URL 渲染，避开 WordPress 仅按标签宽度挑选 `srcset` 缩略图后再放大裁切的问题。此决定按精确组件与素材冻结到 v2 图片策略；同一素材在其它正常比例控件仍保留媒体 ID 与自动响应式选图。该控件仍为原生可编辑图片，前台最终检查须确认实际 `currentSrc` 像素和裁切效果；旧任务不会自动套用。
