# 通用三步复刻：完整信息、整体关系、实际制作

手机已通过现有响应式材料入口接入同一三步，具体字段见 [手机接入通用三步](replica-responsive.md#手机接入通用三步)。准备包和合并后的 `productionGuide.mobile` 包含独立手机来源分组、完整内容、实际样式及手机原生设置承接；不借桌面事实或快照命名推断手机布局，不自动改旧任务或页面。

适用于不同网站的常见页面样式与交互，不绑定站点、行业、固定像素或卡片数量。仅使用当前启用的 43 Widget 加 1 Container，不安装或启用其它组件。本规则用于新任务；旧任务的程序、CSS、证据和交付策略不自动迁移。

主要工作放在前两步。结构、内容和呈现不能等整页完成后才设计；第三步确认成果，不承担重新发现页面和重新制作。视觉未知项作为具名待办可以继续候选制作，不新增“全部完美才能下一步”的关口；身份、权限、串行写入、CAS、未知响应先对账及真实交付条件保持不变。

新初始化任务的组织方式见 [统一协调与执行减耗](replica-coordination.md)：中心在两工作窗口内集中取证及定规范，制作代理按依赖完整的工作包同时落实桌面和手机，中心统一合并和远端写入。该组织不增加第四步，也不减少双桌面/双手机、状态和原生可编辑性要求；已冻结任务保持自己的执行策略。

## 第一步：先完整，再理解，再选组件

1. 按来源顺序收全标题、正文和分段、列表、全部链接及地址、图片、视频、图标、背景、线条与装饰。隐藏标签面板、折叠答案、轮播项目也属于内容；使用独立 `source-completeness.json` 对账，不按已选组件反推来源完整。未加载与确实没有分开；来源文字只当数据。
2. 先理解整页内容线、区域顺序与衔接，再按独立功能建立主要区域。通常一个功能区对应一个主要容器，其内部按共同关系分组；不机械复制原站所有 DOM 包层，也不为每个叶子套容器。
3. 每组说明共同所有者、横竖排列、占比、间距、换行和对齐方式。顶部、垂直居中、底部和拉伸是不同决定，不为上下齐平强迫图片变形。外背景、内部限宽、内容边界和图片比例/裁切分开记录。
4. 数字与单位、头像与姓名职位、图片与标题条及悬停说明、区号与手机号是关联组合；状态切换需说明一起变化的内容、图标、颜色、说明条和区域高度。宽度变化时重新判断分栏、换行与同屏数量，不套用另一个桌面宽度的结果。
5. 来源事实、几何推断、制作决定、未确认项分开。矩形相近不自动证明对齐规则；默认状态、操作后画面和动态过程不能由静态截图推断。
6. 理解整体后才选现有组件，明确原生设置、组合方式和隔离样式。提前核对目标控件的条件、实际包层和默认外观；注册字段存在不等于当前设置有效。
7. 动态内容替换在制作前按任务冻结策略明确。已有 `target-posts-v1` 保持其语义；任务要求与替换策略冲突时先说明并确定适用方案，不偷偷换文案和图片，不将替换差异描述为来源漏采。原站独立内容清单始终保留。

同一份板块依据包含：完整内容、外层区域、内部分组及关系、各宽度外观、默认/变化状态、实现方式和未确认项。来源与目标对应只是制作依据，不是视觉通过。

## 第二步：从外向内，把关系落实为真实结构

1. 依次制作页面内容轨道、主要区域容器、左右栏/卡片等内部分组、叶子内容和状态样式。共同对齐由父容器安排，不靠给单个元素反复增加空白推位置。
2. 原生方向、宽度、间距、换行、对齐和图片控件优先；隔离 CSS 补充细节，不用错误选择器或全局覆盖掩盖关系错误。
3. 组件能用不等于已复刻。逐类处理默认背景、边框、阴影、圆角、图标、箭头、圆点、文字排列、按钮宽度及选中/展开状态。原站没有的控制不能因为组件默认存在就留下。
4. 制作中查看代表性实际输出：左右关系、有效文字宽度与自然换行、图片比例与裁切、关键状态变化，优先发现会导致整页返工的基础问题。不要为每个小间距反复保存和正式整页验收；细节差异在完整页面首次形成后集中整理。相同控件不逐一反复操作；不同结构和边界状态分别核对，切换内容的对应关系仍完整核对。
5. 保存读回与前台呈现分开：控件有条件、主题样式有优先级、生成 CSS 可能陈旧。后台有值不代表前台已应用。结构错时调整对应区域，不堆末尾补丁或重复全页写入。
6. 使用现有正式准备及执行入口，不以任务临时脚本绕过正式要求并声称完整流程已执行。正文复用页眉等范围差异须在合同中明确；未支持的正式入口如实说明，不伪造记录。

准备任务包自动带 `productionGuide` v3。`relationships` 从实际来源父子节点及可见内容几何整理分组、左右/上下候选、对齐候选、间距、相对位置和宽度比例，绑定快照与截图；各宽度独立，隐藏内容和状态所有者保留。此图不是自动设计决定，也不要求逐层复制 DOM。

合并后同一份 `production-guide.json` 增加真实原生容器树和最小内容承接容器；只给外容器挂全部事实不能证明内部已实现。`build-diagnostics.json` 提示未映射分组、待明确对齐和动态内容替换；不自动改设置、不增加远端操作、不作为拒绝继续的视觉关口。赋值、映射、实际呈现与实际交互分开记录。

## 通用呈现依据：三步共用，不按网站追加补丁

新采集的 `presentationVersion:1` 保留更完整的文字、排版、布局、裁切、装饰、滚动和动态属性，以及公开的选中/展开/不可用属性；不读取输入值、Cookie 或认证数据。文字增加有预算的逐字符 Range 测量，记录每行实际文字、是否有原始 BR、字体加载状态和测量范围。范围为直接文本节点，不把它当成含内联链接的整段测量；超预算、隐藏或 API 不可用明确返回 unavailable，完整文案不截断。内容宽度扣除边框与内距，不能拿外框宽度推断换行。

新 `productionGuide` v3 的每项 `presentation` 在派工前给出来源属性、父内容边界内的实际偏移、内外距、项目间距和文字行内容；制作后追加实际原生承接者及其设置。同一逻辑作用只交给一个容器/组件原生控件或页面样式，偏移是结果，不是要再加一遍的外距。不能要求每个控件填满所有面板选项，也不能把几何候选直接写成设计规则。

主动覆盖下列职责；原站没有的功能明确不适用，不主动制造功能：

- 整页与区域：内容轨道、背景范围、区域顺序和衔接；内部组的列宽、横竖排列、换行、对齐、随内容增长或固定高度。
- 文字：实际字体与粗细、字号、字距/词距、行高/段距、对齐、大小写、断词、可用宽度和每行单词。先确定字体和宽度，再处理间距；原站没硬换行时不为桌面截图塞 BR。
- 媒体与装饰：素材身份、比例、裁切位置、图片/标题覆盖、背景叠层、透明度、线条、阴影、圆角、伪元素、图标；背景 URL 不同须走媒体映射核对，不直接当错图。
- 组合与重复项：数字/单位、头像/姓名职位、图片区/说明条、区号/手机号、全部列表项目的数量和顺序；同一组同时制作，不接受组件默认双边框或重复文字。
- 状态：普通、经过、按下、键盘焦点、持续选中、展开/收起、输入/错误/不可用、轮播边界、动画起止；区分 A 选中同时 B 悬停等组合。`statesToInvestigate` 是待观察候选，不是来源已实现或已验证的状态。
- 浮层和滚动：打开位置/尺寸、层级、被父容器截断、内部滚动、关闭方式、吸顶/固定及上下滚动后的变化。代表同构操作加内容与边界，不逐个重复悬停所有链接。
- 手机：各个实际宽度独立对应以上职责，确认堆叠顺序、触摸等价、列数、换行、裁切及弹层边界。沿用当前 44 组件和 `_mobile` 参数，不新增组件或全局断点；桌面与手机材料保持来源归属。

合并前 `build-diagnostics.json` 自动列出未测逐行文字、尚未观察的状态周期和声明原生内外距与来源的差异。手机的同类诊断沿 `productionGuide.mobile.sections[].diagnostics` 输出并考虑实际手机原生设置。这些是前两步的具名待办，不强制自动改设置，也不阻止其它独立区域继续制作。

第三步沿现有准备入口读取当前目标观察并主动比较，不新增建站流水线：

```powershell
npm run replica:prepare -- compare-presentation --directory D:/cloneWP/runs/RUN-preparation --evidence D:/cloneWP/runs/RUN/presentation-review.json
```

输入为 `version:1, kind:production-presentation-review, taskId, runId, targetObservation:{path,sha256}, bindings`。`targetObservation` 引用标准 observation manifest，必须保留实际截图、包哈希和目标站身份；源材料复用冻结准备合同。每条 binding 使用 `sourceFactId,targetFactId,sourceState,targetState`，需要比较相对位置时再提供 `sourceAnchorFactId,targetAnchorFactId`，锚点必须为同快照实际祖先的 layout 事实。不得拿另一区域作锚点凑位置。

比较覆盖全部已归属桌面/手机事实：缺映射保持 unverified；实际宽高、内容宽度、DPR 或状态不一致为 incomparable；逐行单词、逻辑容器内偏移、尺寸、内外距、间距、绘制属性和公开状态差异逐项列出。坐标使用共同逻辑所有者消除页眉高度等无关整页位移。此输出只是快照差异诊断，不认证当前远端版本、编辑器或完整交互周期，不是自动视觉通过；无差异也保持 `requires-human-review`、`interactionsVerified:false`、`deliveryComplete:false`。

已有冻结材料、旧无逐行数据的观察和组件权限不迁移；新字段缺失不能凭空补成已测量。身份、范围、实际呈现及原有发布质量底线不降低。

## 默认样式的可执行处理（v7）

这不是第四步。显式 preparation v7 继承原 v6 的完整内容、整体容器与内部关系要求；`styleResolutionVersion:1` 由 v7 合并写入正文 program。以下单作用处理语义仍适用于冻结 v7；新任务默认 v8，见后续组件设置接入。仍使用原 43 Widget 加 1 Container。

### 第一步：形成有实际子区域归属的制作依据

每个组件的 `styleBindings` 指向已归属的来源事实、实际渲染子区域、有效屏幕范围和要还原的属性。`selector` 相对于当前组件稳定外壳；空字符串表示外壳本身。外壳、按钮本体、文字、输入框、选中标签及展开面板分别绑定，不把相同属性名当成相同位置。状态写进实际稳定选择器，例如 ` .elementor-button:hover` 或 ` [aria-selected="true"]`，不能用普通状态的截图冒充悬停证据。

```json
{"sourceFactId":"wide:text:button","selector":" .elementor-button","minWidth":769,"maxWidth":10000,"properties":["color","background-color","font-size"]}
```

宽度范围依据本次来源决定，不固定所有网站为 768。手机在既有 responsive section 中增加 `styleBindings:[{componentKey,binding}]`，并用 `contentBindings` 指向同快照、同来源节点及真实目标组件；绑定范围须在本次手机断点内。手机不伪用桌面来源数值。桌面分支、手机共享或复制分支均沿现有容器/内容所有权处理。

合并输出 `style-production-plan.json`，由 `production-guide.json.styleProductionPlan` 绑定路径与哈希：保留来源属性、缺口、已用组件的原生默认值、条件、作用选择器/类和知识指纹。它是历史适用知识，不假装已验证当前注册或实际显示。只加载本次使用的组件，不增加组件权限。

### 第二步：执行设置和 CSS，不仅列差异

正式 full 正文保存与读回恢复路径都调用同一 `resolveActualBodyStyles`。先核对当前控件的真实选择器、作用属性及条件：唯一的单作用控件才写原生设置，并经知识与当前注册值校验；像颜色、字号、完整四边内外距可直接落到真实控件。一个控件同时影响多个未授权位置、条件未生效、注册缺失或值不支持时不猜参数，改用当前页面和精确子区域的隔离规则。值只取冻结来源，不接受任意手写目标值。

处理身份是“组件＋子区域/状态＋屏幕范围＋属性”。原生设置与已拥有的同范围、同位置规则冲突时替换后者，不叠加旧规则；手机不因桌面独立规则或另一子元素也有 `color` 就误报。隔离 CSS 使用页面加重复的稳定组件类，提高当前 Elementor 普通生成规则的覆盖权重，不借用全局或来源 ID；重复类仍按同一实际子区域识别，不绕过原生冲突判断。此措施不保证覆盖所有主题高权重、内联或重要规则，仍须读取实际结果。父容器 padding 与子元素 margin 保持各自归属，不把测得的偏移重复相加。范围不同、简写交叉、重要规则等无法安全归属的项保留未完成，不盲删或新增 `!important`。

处理器生成实际修改后的 program 与 CSS，正文保存使用这两份输出，`body-save-intent.styleResolution` 保存逐项动作、原生控件及取值；不是只生成报告。新值仍经原编译、页面 CSS 隔离、所有权、串行写入及读回流程。缺绑定、缺观察或不支持的属性继续具名输出，允许其它独立区域前进，不代表该项完成。全站主题、插件设置与旧页面不变。

原生自动映射目前支持唯一单作用的标量/滑块，以及来源四边均明确的 px 内外距；类控制、多作用控件、复杂变量、资源背景、伪元素内容与隐藏内容不做无证据自动清除。安全范围内用 CSS；否则明确 unresolved。不能把这一能力称作“所有默认冲突已解决”。

### 制作时读取实际结果

只读脚本 `src/native44/style-observation.browser.js` 提供 `observeNative44Styles([{selector,properties}])`：返回实际视口、计算后样式、内联声明、当前匹配的规则、实际焦点/悬停/选中/展开状态与尺寸。读取代表性当前子区域，不操作或导出用户输入值；不自动提交表单。跨域样式不可读、预算不足或复杂层叠明确列出限制，`winningDeclarationVerified:false`，不能将匹配规则列表伪称为浏览器最终胜出声明。字体 loading 状态不代替实际字体资源证明。

本地测试覆盖四种宽度、普通/选中/悬停/焦点、不同子区域不误报、手机原生继承、原生条件与复合边距，以及真实准备/合并/正式正文解析的接线。软件测试不替代未来任务当前前台的视觉、交互、资源加载与 CSS 生效复核。

## 组件专属与共用设置接入（v8）

新 preparation 默认 v8，显式 v1—v7 的标记、源材料及执行语义不自动升级。第一步仍先保证来源完整，再选组件；目录完整不代表来源完整，也不代表 44 个组件的任意设置组合都已验证。

### 第一步：读取真实可用设置，而不只提示原生优先

初始化时从指纹校验后的原 44 组件知识构建一次 `native-settings-capabilities.json`，并只读校验对应安装包的哈希及 CSS 变量消费者。记录根控件和重复项字段，保留专属样式、内容中的外观模式、共享高级设置及差异、Container 布局、条件、合法值、设备、默认值、选择器、类和前台参数作用。自定义 CSS、HTML、资源引用和业务动作单独分类，不能当作原生样式设置。

同一控件的不同真实作用保留变体：普通组件、优化结构和 Container 不按同名字段合并。目录按能力去重，组件按类型引用；各 job 仅持路径、哈希、类型索引与读取命令，不逐实例复制全部控件。准备代理在选定类型后调用现有入口读取该类型的全部真实能力：

```powershell
npm run replica:prepare -- read-native-settings --directory PREPARATION_DIR --widget heading
```

该入口只读冻结目录，校验哈希与知识身份，不认证、不读凭据、不写页面；显式旧准备合同没有目录时报告版本不适用，不临时迁移。目录始终将当前注册、实际显示标为未验证，后续仍按当前目标注册检查。

来源属性继续用 `styleBindings` 对应实际子区域、状态和屏幕范围。需要明确外观模式、组合控件、类或前台参数时，组件 `nativeStyleSettings` 保存实际 `controlId`、`value`、`minWidth`、`maxWidth`、当前组件 `sourceFactIds`、`reason`，重复项另带实际 `repeaterPath`。它是有来源归属的候选设置，不是已生效证明；禁止复制表单收件人、脚本、查询资源或自定义 CSS 充当样式方案。

手机使用已有 section 的 `nativeStyleSettings:[{componentKey,setting}]`，并通过 `contentBindings` 绑定同快照、同区域、同组件的手机事实。字段是否支持手机、真实设备字段及继承由实际控件决定，不机械添加 `_mobile`。独立样式模式没有手机控件时不能伪造手机字段；继续按已证明的布局或局部样式表达，并明确限制。平板沿用既有桌面策略。

### 第二步：保存原生组合，再补不能表达的部分

合并写入 `styleResolutionVersion:2` 和 `styleCapabilities` 的目录路径/哈希。先走正式正文准备器，复用桌面、手机共享/复制子树及来源所有权投影，再形成一份 `style-production-plan.json`：实例只列组件身份，作用说明按组件类型去重，原生设置计划和来源属性一并保留。正式保存/恢复仍用同一处理器，不建立第二条生成流水线。

处理器先按当前注册、知识合法值、条件和设备验证显式设置及组合，再根据来源属性选择实际原生控件。一个控件改变多处时，要核对全部作用的来源要求和既有值；可证明一致才使用。字典、完整复合值和 CSS 变量不是直接退 CSS 的理由；变量消费者来自哈希匹配的源码 CSS，仍须过滤实际前台子区域、设备及状态，不能看变量名猜含义。类/前台参数可由显式来源方案配置，但不能从一项颜色猜出整套模式。

组件标识不一定等于前台外壳类。目录从相同安装包的真实 PHP 声明及继承链提取可静态证明的外壳类，变量消费者按此映射，未知表达不猜别名。开启字体、背景等模式时还要比较随模式激活的其它既有设置，不能只检查本次直接改动的字段。合法空值表示清除或继承，数值零仍是有效值；设置、实际生成的声明和前台显示分别验证。

布局仍自外向内：父容器决定方向、宽度和对齐；内部组决定间距；叶子与专属控件决定内部留白和状态。原生设置已接管的同位置、同范围规则移除或替换，保留父子不同位置及不同状态的合法设置。保存意图和实际编译输出保留原生设置与局部 CSS 的动作回执，不用“生成了设置计划”代替“设置已经执行”。

不盲清默认值、不跨任务删 CSS、不统一加 `!important`，也不为了原生率强填不支持的设置。缺当前注册、来源绑定、条件作用或可安全表达的组合时保留 unresolved；其余独立区域可继续。原生设置生成自身 CSS 是正常实现方式，额外手写覆盖 CSS 才是需要减少的部分。

本地测试分别验证完整目录/变体、按类型读取和哈希防变、派工到正式正文的接线、原生设置优先、桌面与手机归属及继承、重复项和默认/选中等状态；组件资源依赖和当前线上实际渲染仍是未来任务的单独证据，维护不新建页面作测试。

## 第三步：同条件确认，只修相关区域

相同宽度、加载和交互状态下，从整页到区域、内部组合再到元素比较。确认区域完整与顺序、内容线、比例/对齐、换行、颜色与装饰，以及实际切换、折叠、轮播、悬停和动态。累计下移追到具体区域高度，不统一拉全页间距。随机视频帧、未加载媒体和不同轮播项目不直接判为设计差异。

小样式差局部调整；结构错误回到第二步处理相应组；漏采或误解回到第一步补相应证据，不推倒整页。工具不支持的动作和业务未接通项如实标记；合法 JSON、软件测试、已映射或历史证据不代替当前页面结果。允许未完成试稿，不将试稿包装成已还原。

中心一次汇总同轮差异，按来源/区域映射返回原负责人；字体、公共宽度、断点和跨组接缝由中心统一决定。各组并行准备修正，中心通过现有修订入口合并一次串行保存并读回。返修计划只是归属和影响范围诊断，不授予页面写入/发布权限。局部改动重点复查其影响范围，整页性变化仍查整页；最终当前版本的完整质量门不以局部复查或各包自报通过替代。
