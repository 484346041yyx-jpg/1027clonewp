# 独立页眉的通用状态效果

本能力属于 `src/woodmart-header/generic/`，不依附某个站点、页面正文或全站默认页眉。旧方案不自动迁移；没有观察到状态变化时，不填写 `hoverEffects`。

## 1. 采集先于实现

- 对每类不同的菜单效果，记录普通、真实指针悬停、移开恢复三态。除截图外，记录变化作用在链接本身、文字，还是文字前/后的装饰层；记录颜色、尺寸、位置、透明度、位移和动画时长。
- 分开记录当前页标记和悬停效果；下拉菜单还需记录展开/收起状态。不要把当前页已有下划线误认为“所有项目悬停后都常驻”。同构菜单选代表项和边界项，不必逐个机械悬停。
- 搜索框等其他控件分别采集，不能把菜单悬停配置套给搜索框。来源状态缺失或不可操作时，标记未证实，不凭静态截图猜动画。

## 2. 生成时一次映射

桌面 `mainmenu` 元素可选填 `hoverEffects`。每个效果声明 `target`（`link`、`label`、`label-before`、`label-after`）、`normal` 和 `hover`；确有当前页效果时再填 `current`。`currentItemKey` 仅用于来源明确始终强调某个顶级项目的情形，不是通用默认。

例如文字下方的装饰层可使用 `label-after`，将来源观察到的宽度、位置、颜色、透明度、位移和过渡分别写入普通/悬停状态；没有滑动就不要编造滑动。配置由系统生成限定在任务自有页眉与菜单组件内的 CSS，且不能插入文字标签或跨出页眉。手机菜单另按触屏状态设计，不套用桌面悬停。

## 3. 当前页面验收

保存后实际检查代表菜单项的普通→悬停→移开恢复、键盘聚焦、当前页标记与下拉交互；检查另一页眉及正文不被影响。自动测试只证明生成器可用，不能替代当前来源与目标的视觉、交互判断。若不一致，先回看采集和映射，再局部修订，不默认进入整页返工。
