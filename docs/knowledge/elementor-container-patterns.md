# Elementor 组件与容器：通用规则

本页维护跨页面可复用的判断方法。实例用来支持或细化规则；多一份样本、面板或候选记录，不等于多一条通用原则。具体节点、数值、资源和观察过程留在实例档案中。

## 1. 按内容、数据与编辑模型选组件

先判断内容由谁编辑、数据从哪里来、每项是否需要独立布局，再选 Widget。标题、正文、单图、图文卡和真实业务动作各有职责；外观相似不能证明组件可互换。

经典 `slides` 将背景、文案和链接保存在 Repeater 项中；`wd_nested_carousel` 的项目可以有真实子容器和原生内容。先确认编辑模型，再决定是否需要子容器。图片已含完整广告文案时，应检查点击范围与裁切方式，避免重复叠字。

单品详情 Tabs 组织当前商品内容，商品集合 Tabs 为各项组织独立查询；`image-box` 可承担图文说明，是否可点击取决于实际链接字段。

**组件身份与字段数据源同时判断。** 文本组件可通过动态标签读取当前商品正文，普通按钮也可能被配置为控制同一容器的展开；不能只按 Widget 名称复制静态文字或推断动作。先关联动态标签、内容提供器、控制器与共同所有者。静态配送说明和服务卡可以复用通用组件；商品图库、价格、购买、评分和评论不能因外观相似而降为普通图片、文本、按钮或营销评价。

**按共同职责选择组合。** 普通导航列按 COMPONENTS 的既有规则使用标题与列表；真实行动入口才使用按钮。静态分类入口先评估完整图文组件，只有独立编辑槽、多个点击区域、内容顺序或现有字段不足等具体理由，才组合标题、说明、图片和 CTA；来源用了多个 Widget 本身不是拆分理由。标题、数据集合与“查看全部”入口可以组成栏目，查询仍归集合组件；服务说明可由图文组件组织，集合父级仅负责网格或轮播。具体实例和数值留在档案，不按品牌另造选型原则。

## 2. 独立核对查询与业务上下文

栏目标题、标签文字、模板名和当前样品不能单独证明查询。每个商品集合、每个 Tab 分别检查来源、筛选、排序依据与方向、偏移和排除；相关商品、畅销、最近浏览等不能靠标题猜测。

相同显示文字可能来自不同字段，相同商品也可出现在不同的合法集合位置；先核对字段、查询和显示职责，再判断是否需要去重。

设备分支中的列表与 Tabs 还须逐项对账文字、顺序、实际目标和查询。仅复制了名称或外观、链接仍为裸 `#` 且无明确页内目标或动作、或者缺少必要筛选，均作为待修正反例，不作为可用配方。合法锚点和具名交互另行判断，不能一概删除。重复设备结构不能成为业务内容分叉的理由。

归档的工具栏、筛选和结果应服务同一归档上下文。单品图库、标题、价格、购买、详情和评论应绑定同一当前商品。营销集合不能替代归档结果，静态价格或普通按钮不能替代商品业务能力。编辑器样品与线上页面上下文不同，应保留限定，先核对再判断。

单品还要区分简单商品、可变商品及独立链接商品：属性选择、匹配变体、图库、价格区间/选中价格、货币、促销、库存和购买状态共同属于当前商品。属性选择框不等于链接变体组件，HTML 按钮没有 disabled 属性也不证明可以购买；还应读实际状态类和选择条件。分享模式可以动态生成当前商品链接，不能仅凭编辑器中的占位链接判为失效。详情标签与独立评价组件同时存在时，核对是否重复输出相同评论、表单及 DOM ID，确定一个主要内容所有者，不把重复业务表单作为标准组合。

复刻商品区时，来源商品事实与目标选品分开：目标使用真实 WooCommerce 商品，具体图片、名称、价格和类别可不同；来源卡片布局、文字样式、间距、图片显示框及轮播控制仍须由原生可编辑组件实现。未指定选品和“后面自己弄”不等于放弃整个商品区，不据此转成静态假卡或空占位。

## 3. 按职责识别容器与真实元素

容器应承担可说明的职责，例如背景与留白、居中限宽、横向分列、卡片分组或嵌套内容接口。共同父级管理列宽、gap 和对齐，子项自然撑高；不为每个叶子机械包层，也不因层数多就盲删。

复刻固定高度的正文滚动区时，先确认现有 Container 是否只承载该正文。若是，直接在该容器设置高度与纵向溢出即可；只有同级还混有不应滚动的内容时，才增加内层容器分组。以实际滚动节点、可见高度和滚动后内容可达性验证，不用截图裁切或隐藏正文冒充滚动。

Elementor 元素身份与运行 DOM 分开。`.e-con-inner` 可能承担实际限宽和排列，但不另计 Container；Swiper 轨道、克隆和控制器也不增加逻辑内容项。读取布局时找到真正承载子项的节点，不能只看最外层样式。

旧 Section/Column 可以与 Container 共存，按真实身份记录；学习不自动迁移结构。共享页眉页脚与编辑器选择框、拖放提示也不属于页面正文。

单品模板内引用的共享 HTML Block、动态内容提供器、主题粘性购买栏、手机工具栏与第三方聊天浮层分别记录所有权；它们不自动成为模板的子 Widget。共享面板的内容、内部响应式与资源绑定需单独检查，来源资源 ID 只作定位。浮层遮挡或多层内边距挤压属于需要重新判断的问题，不能因来源存在就原样复制。

图片、背景与叠加内容也要分清所有者：原生图片可按比例随宽度变化；背景照片的显示由容器尺寸、位置和裁切共同决定；同一容器可以有设备专用素材。先确认素材内是否已有完整文案，再决定是否放置原生文字和 CTA。来源的多设备图片槽只证明该实例的编辑模型，不自动扩大目标平台的设置能力。

## 4. 保留参数含义，并核对布局行为

复用的是参数职责，不是样本数值。外层限宽、组件高度、图片资源尺寸与显示裁切分别判断；结合实际布局节点、内容流、Flex 收缩和可见效果核对，不能只凭宽度之和推算最终几何。

**原始值与计算结果分开。** 保留控件原始数值、单位以及空值、显式 `0`、继承的区别；浏览器 computed style 是当前环境的结果，不能反写成组件显式设置。字段名称近似也不代表单位或语义相同。

**当前模式与字段生效条件分开。** 保存过某字段，不代表当前正在使用它。先核对布局、皮肤、父级开关和设备条件，再记录实际生效的字段：网格模式的列数与轮播模式的每屏数量不同，残留的自动播放或轮播字段不能证明网格在轮播；`static` 标题状态也不能证明折叠交互。字段的间隔、过渡速度和单位按各自合同解释。原始保存值、编辑器补入的默认/空值、运行时结果分别保留，不能把一份展开后的设置对象当作全部显式配置。

**集合数量与滚动行为分开。** 查询项数、每屏项数和滚动步长独立记录；分页、循环、自动播放与暂停又各有设置。面板值只能证明配置状态，实际切换和布局表现仍需观察。

**长文本的页内滚动也要确定所有者。** 来源出现独立滚动条时，分别定位外层布局、有限高度的滚动视口和内容组件；不能把页面滚动或文字被截断当成同一效果。先记录标题在视口内还是外、视口实际高度与内边距、`overflow`、内容总高度，以及桌面和手机是否保持独立滚动。用已有 Container 承担视口、原生标题与正文 Widget 承担内容；只有确有独立布局职责时才增加内层 Container，不因视觉上有滚动条新增 Widget。原生 `overflow: auto` 仍须配合有证据的高度上限，必要的尺寸和滚动条细节只写本页隔离 CSS。来源的 258px 等实例数值不成为通用默认值。

验收要在实际页面分别确认滚动前后内容、底部可达、滚轮/触控作用于正确区域、横向无溢出，并核对视口外标题是否保持不动。仅有合法组件树、`overflow` 设置或静态截图，不足以证明滚动行为。标题在滚动视口内与在滚动正文外，是两种不同的层级，不能机械套用同一组件树。

轮播宽度、gap 和索引可能由运行时计算；CSS 外观修正不能替代原生参数。先核对实际容器、内层轨道和控制器，再用两桌面读回及真实切换验证。页面自定义 CSS 按模块集中维护当前完整版本，修订合并既有规则，保留必要级联顺序；不能持续追加覆盖掩盖结构、资源、查询或交互失败。

**手机适配先选机制，再确定参数。** 同一结构可用原生设备字段调整宽度、换行、字号、间距、每屏数量和图片槽；只有设备间的内容组织或交互模型确实不同，才评估独立分支，并明确显示/隐藏条件。先核实该分支所需组件和目标能力，再逐项保持内容与链接一致；不把两套结构设为统一默认。核对百分比宽度的实际参照父级、`vh` 高度和 `cover` 裁切，不能把横幅等比缩小、固定高度裁切和设备换图混为同一种实现。

手机字段为空时继续核对继承、主题响应式与运行时结果；实际每屏项数不能反写成该字段显式值。标题、按钮内边距、卡片宽度与父级换行一起判断，不只改字号；大幅位移、负边距和固定高度只留作实例，不能无条件复制。编辑器可能显示半透明的设备隐藏区域，实际显示归属须结合设备设置与前台核对。滚动视口与“展开更多”的折叠容器是不同机制，各自验证控制器和内容可达性。

检查手机生效链时同时读取父级隐藏、主题断点、组件设备字段及共享内容块自己的媒体查询：父级隐藏后，子项的手机列宽不构成实际手机方案；全宽设计选项也不保证数量框和多个购买按钮分别独占一行。轮播有箭头不等于手机可操作，需确认控制器位于有效视口、实际轨道变化及滑动前后结果。自动播放配置、一次索引读回和点击成功响应都不能代替行为验证；第二手机宽度、触控或真机未测就保持未验证。

## 5. 分清实例证据、资源与能力

页面实例证明“这页用了什么”，组件目录说明“可以选什么”；精确 Widget 身份不能由中文名称代替。空文字不一定没有图片，空预览不一定未绑定资源，无子 Widget 的容器也可能有背景内容。

通知、活动筛选、变体等上下文组件可因当前状态而无正文，编辑器空占位不能直接判为缺块或当作前台内容复制。

来源的商品、优惠、资源 ID、URL、浏览历史与尺寸不进入通用默认值；Sidebar、媒体、品牌、文章及业务查询需在目标重新确认。实例观察、源码、注册、保存、呈现和交互是不同证据，不能相互替代。历史学习记录保留为候选资料；学习不自动启用组件或扩大执行权限。

学习档案按“内容职责 → 组件组合与所有者 → 模式/条件 → 原始设置与设备覆盖 → 运行时与截图范围 → 缺口/反例”关联。已有原则的新样本合并到原段落，精确数值和节点单独留档。编辑器点击被接管为选中组件或切换文档时，只能证明编辑上下文变化，不能记作前台交互通过；看到 `posts`、自定义 HTML 或未启用组件也不授予生成权限。缺少完整观察包或截图文件时如实保留证据等级，不伪造学习 CLI 的保存、呈现或交互资格。

把“当前商品无输出”“状态条件未满足”“功能不存在”分开；未显示的倒计时、属性表、组合购、链接变体或评价只保留具名待核实项，不补固定数据、不认定原因。已有组件身份、查询适配、单品模板/预览绑定、共享资源与业务服务资格也分别判断：固定 ID 商品集合不证明 related、bestselling 或 recently_viewed 查询可执行；组件源码研究不证明目标已注册、能保存或所有模式已通过。缺口留在规划中，不能通过静态假内容或扩充名称白名单消除。

新闻/News/Blog/文章推荐等重复文章列表使用原生“博客” `wd_blog`，栏目标题与外容器仍各自负责标题、背景和限宽。默认动态读取目标站已发布文章，日期降序，数量与参考区域接近；文章自身标题、摘要、日期、特色图和链接来自目标记录，样式接近参考区域即可。判断依据为文章列表职责与卡片槽位，不仅依据栏目文字。这个替换仅限明确文章区，不扩展到普通营销卡。分类/标签使用已核对的目标 ID，当前查询观察 ID 只作当次前台验证，不写成固定文章列表。整页与 CSS 完成后统一检查真实原生组件、文章顺序和链接、可绘制特色图、标题及布局；选用轮播或加载更多还需实际交互证明。原生结构树名称无需另取别名。
