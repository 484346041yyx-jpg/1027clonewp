## 是否可脱离 Codex（查证结论）

- 远端写入不需要浏览器登录态：`src/wordpress/client.ts:108` 用 Basic Auth（username + applicationPassword）。
- 编辑器收尾也不需要用户 Chrome 会话：`src/verification/capture-target.ts:100` 支持注入 `ScopedBrowserAuth.cookies`，配合 `novamira/create-admin-access-link` + exchange 取得后台会话；`editor-completion/session.ts` 经 `createScopedContext(browser, editorUrl, auth)` 建立。
- 结论：整条链（采集 Playwright 自开 Chrome → Basic Auth 写入 → cookie 注入编辑器）不依赖 Codex 桌面扩展或用户标签。技术上可脱离 Codex。
- 真实变量只剩模型判断力：regions 选择器、组件选型、隔离 CSS、看截图验收。代码门保证下限，模型看图能力决定上限。
- 建议验证方式：拿内页小样跑一次草稿（不发布），比讨论更有效。

## /index 替代首页 + 准备链全关卡（重要）

- **不改系统的解法**：`https://www.huaqipackage.com/index` 返回与首页完全相同的 title/内容（200），可作为来源；`/index.html` 也可以但含点不符合 slug 正则。slug 必须等于 `index`，页面落 `/index/`。用户若要 `/huaqi-package/` 只能在后台手改 slug。
- 准备链实际踩到的 12 个校验（按出现顺序，下次可一次过）：
  1. `knowledge` 必须带 `fingerprint`（取自 `data/native44/index.json` 的 fingerprint 字段，不是文件 sha256）
  2. `targetEnvironment` 必须写字面量 8.5.5/1.1.8/3.35.4/3.35.1
  3. `responsive.version` 必须 2 且带 decisions；readonly header 需要 `mode:reuse-readonly`+requestRef+reason+headerId+sharedHash+evidence
  4. `compatibility` 不允许 `unresolved`
  5. `source-evidence.json` 必须带 `additionalEvidence` 指向 hover-review
  6. `componentGuidanceReview.guideSha256` 必须等于 `packet.componentGuidance.source.sha256`（知识文档哈希），不是快照文件哈希
  7. `componentKeys` 必须包含 section.key 本身，且主容器 key 必须等于 section.key
  8. `phoneMode` 必须等于 section.responsive.mode
  9. 每个 block key 必须以 `${sectionKey}_` 开头（主容器除外）
  10. 容器必须绑定该 section 在 plan 里的**全部** sourceFactIds（两个快照），只绑 1920 会报 section_content_incomplete
  11. `role` 枚举只能是 heading/text/image/button/link/card/layout/carousel/product/navigation/form/decoration/other
  12. `form` 与 `wd_blog` 均报 `native44_resource_adapter_unverified`（无目标资源适配器），只能用静态内容替代
  13. source-units 的 nodeIds 必须覆盖该区域全部节点（取自 `sourceFacts.snapshots[].nodes`），否则 `replica_full_body_header_coverage_missing`
- **最终阻断**：`replica_full_reuse_resources_changed`。`footerHash`（reused-driver.php:21）对全部 `cms_block`/`woodmart_layout` 的 post 对象、菜单对象、theme_mods 做 digest，连续读取会变化（实测 2ad36ff7→50982725），导致冻结值与建页时读取值必然不一致。站点本身最近修改是 06:09（codex 单品任务），之后无变化，所以不是并发写入，而是该 digest 包含非确定性字段。
- 影响：`pageScope:body-only` + 复用页脚的路线在当前实现下无法完成建页。可选：改系统让 digest 排除动态字段（用户禁止）、改整页任务不复用页脚、或停止。
